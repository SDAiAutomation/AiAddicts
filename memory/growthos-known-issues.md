Issues found reviewing GrowthOS on 2026-09-03. Items 1-4 + 6 fixed the same day.
Committed as `bdcdfcf` and pushed to branch **`growthos/mvp`** (renamed from
`claude/project-feedback-scs61n`). GrowthOS lives on its own branch — no PR, not
merged into the FI Validator's `claude/fi-validator-rag-ksdjI`.

1. **[FIXED]** ffmpeg subtitles path broke on Windows — `engine/video.py` `render_final()` now runs ffmpeg with `cwd` set to the `.srt` folder and references it by bare name, plus a `_run()` helper that surfaces ffmpeg stderr and a clear "install ffmpeg" message.
2. **[FIXED]** Stale checklist — `engine/publish_pack.build_checklist()` now emits the `log_metrics.py <id> --mark-published` command instead of referencing the removed `metrics/suivi-hebdo.csv`. `write_pack()` / `build_checklist()` take an optional `content_item_id`; `assembler.run()` reordered so the Supabase write happens before the pack.
3. **[FIXED]** No retry/resume on ElevenLabs — `engine/tts.py` `synthesize()` retries network errors + HTTP 429/5xx with exponential backoff (3 attempts), fails fast on other 4xx. `assembler.run()` reuses per-block audio and the final video already present under `output/<slug>/`.
4. **[FIXED]** get_or_create race — `engine/repo.py` `get_or_create_account()` is now an `upsert` on the `(organization_id, platform, handle)` unique constraint. `get_or_create_organization()` stays select-then-insert on purpose (no unique constraint on `organizations.name`, and a global-unique org name would be wrong for real multi-tenant).
5. **[MIS À JOUR 2026-10-04]** Le web (growthos-web) travaille avec la session de l'utilisateur (`createServerClient`, donc RLS réellement appliquée) ; le `service_role` n'y sert que pour l'admin, les actions serveur qui doivent contourner la RLS et les API machine (AutoEdit, cron). Le moteur Python reste 100 % `service_role` : voulu, c'est un worker de confiance.
6. **[FIXED]** Audio concat gaps — `engine/video.py` `concat_audio()` switched from the concat demuxer + `-c copy` to the concat *filter*, output `full.wav` (lossless) instead of `full.mp3`. `assembler.run()` updated to pass `full.wav`.

ffmpeg: **now installed** on the user's Windows machine (ffmpeg 9.0.1-full_build, verified 2026-09-03 in a later session — the earlier "not installed" note is obsolete). The video half of the pipeline can now be run locally; a real ElevenLabs call still needs a valid key + voice_id in `.env` (currently `.env` == `.env.example`, placeholders only). Pure-logic unit tests: 24 pass.

**Passage à plusieurs users — mis à jour le 2026-10-04.** L'état du 2026-09-05 (aucun crédit branché, FIFO global, clés partagées sans garde-fou) est DÉPASSÉ :
- **[FAIT] Quota / crédits.** `engine/assembler.run_for_content_item()` appelle `repo.reserve_generation_credit()` AVANT le premier appel payant (RPC atomique `reserve_generation_credit`, `organizations.credits_balance` + grand livre `credits_ledger`, plan `business` illimité), rembourse si le run échoue (`refund_generation_credit`) et lève « crédits épuisés pour ce mois-ci » : le worker passe alors l'item en `failed` avec cette erreur (jamais silencieux). Politique de retouche : 1 retouche gratuite par vidéo (migration `20261003120000`). Limites par plan : comptes (trigger SQL), quota d'appels IA (`consume_ai_quota`), crédits (`20260920190000`, `20260921120000`). Les chiffres de plan (crédits par mois) vivent dans la config Stripe/web, PAS dans ce fichier : ne pas les recopier ici.
- **[FAIT 2026-10-04] Équité du worker.** `repo.claim_queued_item()` garde le FIFO tant qu'une seule organisation attend (aucune requête de plus) ; avec plusieurs organisations, `repo.pick_fair_item()` fait un tourniquet : l'item le plus ancien de l'organisation servie le moins récemment (d'après les `generation_started` de `product_events`). En cas d'erreur de lecture, retour au FIFO avec une ligne dans le journal. Limite : le worker reste en série (un job GitHub Actions, 1 vidéo à la fois) ; il n'y a donc pas de plafond de jobs simultanés à poser, seulement l'ordre de passage.
- **[FAIT 2026-10-04] Clés partagées.** `engine/retry.py` : délai `Retry-After` du fournisseur (plafonné) sinon backoff exponentiel + jitter. ElevenLabs (`engine/tts.py`, 2 fonctions) : 5 tentatives au lieu de 3 (~30 s), erreur finale explicite « limite de débit ElevenLabs sur la clé partagée » sur 429. Pexels (`engine/visuals._pexels_get`) : 3 essais sur 429/5xx, et une ligne de journal quand le plan retombe sur le visuel de repli (avant : repli sans aucune trace). OpenAI images avait déjà `Retry-After` + cadence globale.
- **[OUVERT] Pas de quota par organisation sur les clés elles-mêmes** : un 429 reste possible si une organisation sature la clé ; on le traite (attente, erreur claire) mais on ne le prévient pas. À reconsidérer seulement avec plusieurs workers en parallèle ou plusieurs vraies organisations actives.
